Thank you, Zoe_M, this is exactly the test I needed: a real multicolour file against a real shelf. All three points are in the tool now (commit 66fb092, same URL, `node --test` 14/14 with two new cases built from your screenshot).

**1. Picking a colour without knowing the hex.** Under "Your spools" there is now a name field, a colour box and an "Add spool" button: type the name, pick the colour visually, and the `name,#RRGGBB` line is written for you. If Snapmaker can share the sRGB values of the Snapspeed PLA range, I will ship them as a one-click preset, so a slot can be filled by picking the spool instead of the colour.

**2. "Used: no" next to 60.2 cm².** That was a bug, not a wording problem. The Santa's unpainted faces print in filament 1 (the object names no extruder in `model_settings.config`, so the slicer falls back to filament 1). The tool measured that surface and still called the filament unused, because it only trusted the extruder list. Now any filament that prints surface is used; in your file the red #C12E1F becomes the fourth colour and gets the red spool (dE00 11.9). The number is surface, not weight: the column is now called "Printed surface" and says so. The tool never slices, so it cannot know walls, infill or layer height; grams are the slicer's job. For a colour decision the visible surface is the number that matters, and it is what weights the merges (dE00 x cm² repainted).

**3. dE00 45.81 is not a recommendation.** Agreed. Above dE00 25 nothing on the shelf is even the same colour family (red vs dark red is 23.8, navy vs black 29.7, white vs yellow 30.5), so the slot now reads "No spool in reach: load a spool near #FFFFFF", names the nearest spool and its distance, and no longer takes a spool away from another colour. With your four spools the Santa plan becomes: T1 #C12E1F -> Snapspeed red, 11.9; T2 #000000 -> Snapspeed black, 0.0; T3 #FFFFFF -> no spool in reach (nearest yellow, 30.5); T4 #F0BE02 -> Snapspeed yellow, 17.7.
